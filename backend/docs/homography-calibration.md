# カメラ校正 (image->grid homography)

カメラ画像上の座標を会場マップのグリッド座標へ変換するための、カメラごとの
射影変換(homography)校正。**マップ契約(`/map`)には一切手を入れない**。校正は
バックエンドが持つ「カメラごとの設定」であり、対応点はカメラ単位で保存する。

## データモデル

`kv` テーブルにキー `calib:<camera_id>` で1レコード。追加マイグレーション不要
(既存 `kv` を使う・冪等)。保存形は次の record 形:

```
{
  "matrix": [[..],[..],[..]],     # 解いた 3x3 homography
  "image_points": [[x,y], ...],   # 正規化画像座標(0..1) の対応点(4点以上)
  "grid_points":  [[u,v], ...],   # 対応するグリッド座標
  "reprojection_error": 0.0,      # 当てはめ品質(グリッドセル単位の RMS)
  "updated_at": 1699999999.0
}
```

- **対応点(image_points / grid_points)を保存する**ので、後から再表示・点の
  追加/削除・再計算・監査ができる。
- 旧形式(行列だけの bare list)も読める(後方互換)。`load_calibration()` は
  常に行列だけを返し、`/ingest` はそれを使う。

## API

### POST /admin/calibrate

対応点(4点以上)を渡すと homography を計算・保存する。

```json
{
  "camera_id": "cam-1",
  "image_points": [[0,0],[1,0],[1,1],[0,1]],
  "grid_points":  [[0,0],[10,0],[10,8],[0,8]]
}
```

応答: `homography` 行列＋`reprojection_error`＋受け取った対応点。

- **退化配置は 400 で拒否**する(3点以上が同一直線＝homography が定まらない)。
  誤った校正を黙って保存しない。
- 点数が4未満は 422 (pydantic バリデーション)。

### GET /admin/calibrate/{camera_id}

保存済みの行列＋対応点＋再投影誤差＋更新時刻を返す。未校正は 404。

### 認可

`/admin/*` は `KUMU_ADMIN_AUTH` が有効なときだけ Bearer トークンを要求する
(既定は off = 従来どおり素通し)。校正エンドポイントもこの共通ゲートに従う。

### /ingest との結線

`/ingest` はカメラに校正があれば homography で画像座標→グリッド座標へ射影し、
無ければ従来どおり素朴なスケーリングにフォールバックする(非破壊・opt-in)。応答に
`"calibrated": true/false` を返す。

## iOS 校正導線 (設計提案 / 未実装)

実機カメラのプレビューと会場マップへのタップ操作が必要で規模が大きいため、
本PRでは実装せず設計提案に留める(バックエンドは受け入れ準備完了)。

### フロー案

1. 設定に「校正モード」を追加。カメラプレビューを静止表示。
2. **基準点を4点以上**、以下を1組ずつ登録:
   - プレビュー画像上の点をタップ → 正規化座標 `(x,y)` を得る(0..1)。
   - 会場マップ(グリッド)上の対応セルをタップ → `(u,v)` を得る。
   - 会場の角・棚の端など、地面の平面上で見分けやすい点を選ぶ。
3. 4点そろったら `POST /admin/calibrate` に `camera_id` と2配列を送る。
4. 応答の `reprojection_error` を表示し、大きければ点の打ち直しを促す
   (「基準点がずれている可能性があります」等、数字ではなく平易な文言で)。
5. 既存校正は `GET /admin/calibrate/{camera_id}` で読み戻し、点を再表示・編集。

### 実機で必要になる部分(構造のみ)

- カメラプレビューの座標系 → 正規化座標への変換(検出パイプラインと同じ正規化)。
- プレビュー上のタップ座標の取得(`AVCaptureVideoPreviewLayer` の座標変換)。
- マップ表示コンポーネント上のセルタップ取得。
- `APIClient` に `calibrate(cameraId:imagePoints:gridPoints:)` を追加(薄いPOST)。

これらは実機(カメラ・会場)前提のUIのため、実装フェーズで別チケット化する。
バックエンドの契約は本PRで確定済みなので、iOS側はこの契約に対して作れる。
